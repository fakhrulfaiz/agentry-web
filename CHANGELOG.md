# Changelog

All notable changes to Agentry Web are recorded here.





## 2026-11-25 — run the published image without the repository

- `deploy/compose.yaml` and `deploy/agentry-web.env.example`: run `ghcr.io/fakhrulfaiz/agentry-web` with Docker Compose and a settings file. Each GitHub Release attaches both, the compose file pinned to that version. README "Running the published image".

## 0.2.0 — 2026-11-25

- One compose file (`deploy/compose.yaml`, attached to the release) runs Agentry from the published images: web only against your own API, or the full stack (`COMPOSE_PROFILES=full`: Agentry Web, the Agentry API and Postgres), with one settings file (`agentry.env.example`). In full mode the web app waits until the API is healthy.
- Fixed: signing in over plain `http://` on a LAN address or a server's port failed in production (the session cookie was always `Secure`). It is now `Secure` when the request came over HTTPS; `AGENTRY_WEB_COOKIE_SECURE=always` forces it behind a TLS proxy that does not send `X-Forwarded-Proto`.

## 2026-11-25 — sign-in over plain HTTP in production

- `deploy/compose.yaml`: in full mode the web container starts once the API is healthy (`depends_on` with `required: false`, so web-only mode is unaffected). With the API's `/health` now waiting for its database (dsh-agents-api `976bab2`), sign-in no longer races the API's start; verified order postgres → api (first `/health` 503 `starting`) → web.
- Fixed: a production deployment opened over plain `http://` on anything but localhost (a LAN address, a server's container port) could not sign in, because the session cookie was always `Secure` and browsers drop it there. It is now `Secure` when the request came over HTTPS (`X-Forwarded-Proto`, which Next also sets from the connection); `AGENTRY_WEB_COOKIE_SECURE=always` (new, default `auto`) keeps it `Secure` on every request for a TLS proxy that does not forward the protocol. Verified on a production build over a LAN address: signs in now, and fails as before with `always`.

## 2026-11-25 — one compose file for the whole stack

- `deploy/compose.yaml` runs Agentry from the published images in two modes (`COMPOSE_PROFILES` in `.env`): `full` (Agentry Web, the Agentry API from `ghcr.io/fakhrulfaiz/agentry-api`, Postgres 16; the web app uses the API at `http://api:3080`) or web only (against your own API, `AGENTRY_API_URL`). One settings file, `deploy/agentry.env.example` (replaces `agentry-web.env.example`); each service gets only its own values. Agentry Sandbox stays separate (`AGENTRY_SANDBOX_URL` / `_KEY`). Verified both modes locally: full-mode sign-in with the dev key and the web app's API calls through the bundled API, and web-only reaching an API on the host. Releases attach the new file names.

## 0.1.0 — 2026-11-25

First tagged release: the claude.ai-style Agentry frontend (sign-in, chat with live reasoning and tool cards, trajectory view, agents, scheduled tasks, artifacts, plugins and skills, sandboxes), with faster navigation, user message actions, the launchers, the Docker image and CI described in the entries below.

## 2026-11-25 — versioned releases

- A `develop` → `main` merge is a release of `package.json`'s version: the pull request fails when that version already has a `v<version>` tag, and `publish.yml` pushes the image, tags `v<version>` and creates the GitHub Release (notes from this file's `## <version>` section, `scripts/ci/release-notes.sh`). An already released version is never published again.

## 2026-11-25 — CI and GHCR

- GitHub Actions: `ci.yml` (push to `develop`: typecheck + Vitest; pull request to `main`: also Playwright e2e and a Docker build check) and `publish.yml` (merge to `main`: image to `ghcr.io/<owner>/agentry-web` as `<version>-<sha>`, `<version>`, `latest`).
- `scripts/start.sh` pulls the GHCR image when no local tar is there (`--ghcr` to prefer it), and names Docker Desktop's lost credential session when that is why a pull fails.

## 2026-11-25 — Docker image deployment

- `Dockerfile` (Next standalone server, no configuration baked in) and `scripts/dev.sh image`, which builds it and exports `dist/agentry-web-<version>-<commit>[-dirty].tar`. `scripts/start.sh` now deploys the newest tar: loads it unless already loaded and replaces the container `agentry-web` (restart unless-stopped; env from `.env`/`.env.local` with a loopback `AGENTRY_API_URL` pointed at `host.docker.internal`; `.data/` mounted for connector keys). Without a tar it offers to build one or to run without Docker (`--no-docker`). `output: 'standalone'` is set only for the image build (`AGENTRY_WEB_STANDALONE`).

## 2026-11-25 — launchers

- `scripts/start.sh` (production build + `next start`, rebuilding only when the source changed) and `scripts/dev.sh` (`next dev`). Both check that the Agentry API answers `/health` first and offer to start it in herdr, wait, continue or quit (`NONINTERACTIVE=1`: wait, then fail), and refuse a busy port. Menus use gum 0.17.0 when present (offered into `.tools/bin`), else plain prompts.

## 2026-11-25 — faster sidebar navigation; user message actions

- Sidebar clicks no longer wait on the server. Every signed-in page is dynamic, so Next prefetched nothing and kept no client copy: in-app links now prefetch their page in full (`AppLink` in `AppTheme.tsx`; `/api/` links are left alone), and `experimental.staleTimes.dynamic` keeps a visited page for 60s. Measured on a production build against the mock API: 0 server requests per sidebar click (was 1 each). `next dev` stays much slower (it compiles each route on first visit and never prefetches): judge speed on `pnpm build && pnpm start`.
- Scheduled, Agents, Artifacts, Sandboxes and Plugins › Skills show the data they last loaded at once when opened again and refresh it in the background, instead of a skeleton on every visit (`useCachedState`, `src/ui/page-cache.ts`; memory only, cleared by a reload or sign-out).
- Opening a chat again shows its last read history at once while it reloads (an idle session's status too; a running one waits for a fresh status, so no stale approval is offered). Opening a chat now asks for the session together with its items instead of after them, one round trip fewer.
- Hovering your own message (or tabbing into it) shows Retry, Edit and Copy under the bubble, as in claude.ai. Retry sends the same text again; Edit opens it in place (Enter sends, Escape cancels) and sends the edited text as a new message, since the backend has no branching. Retry and Edit are hidden while a turn runs.
- New chat: the Agent and Environment menus moved out of the composer to a row under it, each capped in width, so a long sandbox name truncates instead of crowding the input. They are hidden while the first message is being sent.
