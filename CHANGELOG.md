# Changelog

All notable changes to Agentry Web are recorded here.

## Unreleased

- 2026-11-10: New-chat composer follows claude.ai's proportions: a shorter two-line input (the earlier height was too tall) with a larger corner radius (`--radius-chat` 1rem, which the open-chat composer shares), and a "Recent files" row under it with the newest files from the latest chats (`src/ui/chat/RecentFiles.tsx`); each opens its chat with the file in the preview panel.
- 2026-11-10: The Scheduled tasks and Agents pages list their entries as cards instead of tables (`src/ui/cards/EntityCard.tsx`): the title is a link stretched over the whole card, a task card keeps its pause switch and menu on top, and the footer carries the facts (agent: tools, preferred apps, subagents; task: run state and next run). Paused and ended tasks are dimmed; two columns from 640px, one on phones.
- 2026-11-10: Agents page (`/agents`, sidebar "Agents"): each signed-in user creates, edits and deletes saved agents (name, model, reasoning effort, instructions, Host tool allow list as `host_tools.allow`, preferred Composio apps as `metadata.connectors`, subagents as `multi_agent`), with eight bundled starter agents inspired by ECC (MIT). New chats get an agent menu beside the model menu (sends `agent_id`); when the chosen agent has preferred apps the proxy adds a soft "use only these connected apps" line to that session's instructions. The proxy allow-list now permits `POST /agents` and `POST`/`DELETE /agents/{id}`. The new-chat composer is taller. Scheduled runs do not get the connector key or the app limit (the backend creates their sessions); there is no schedule agent picker because schedules are created from chat. Spec: `docs/superpowers/specs/2026-11-10-agents-page-design.md`.
- 2026-11-10: Theme changed to a shadcn-style palette (`src/ui/theme/brand.ts`, rebuilt `agentry.{css,js,d.ts}`): blue accent `#3b82f6` (darker/lighter variants for text in light/dark), flat neutral whites and greys with a `#171717` dark base, `0.375rem` element radius with a tighter radius scale, Inter for body and headings (the serif headings are gone), JetBrains Mono for code. Shadow, chart and Tailwind tokens from the source palette are not used.
- 2026-11-10: Preview panel redesigned in the manner of claude.ai's artifact panel: a floating rounded card with the file's icon, name and type on the left and a Preview | Code switch with Copy, Download, Files and Close icons on the right; tabs only appear with more than one open file; the tree opens beside the file from the folder icon; the content area now fills the card (files previously collapsed to no height); the file refreshes when a turn ends. Word documents (`.docx`) now preview: converted to HTML in the browser with `mammoth` and shown in the same sandboxed iframe (document-style, not exact page layout); `.xlsx`/`.pptx` still offer download.
- 2026-11-10: Preview panel in the chat page (spec `docs/superpowers/specs/2026-11-10-preview-panel-design.md`). A resizable right-hand panel with a Files tab (the sandbox tree, hiding `.venv`/dot paths/`uploads/`) and one tab per opened file, opened from a chat file card, the new "Files" header button, or an Artifacts row (which now links to `/c/{id}?file={path}`). Renderers: rendered Markdown, highlighted code (`highlight.js`), images, PDF, sandboxed HTML (empty `sandbox`; "Run scripts" adds only `allow-scripts`), CSV/TSV tables (2,000-row cap), JSON tree, text; other types offer download. Message attachments still use the old preview dialog (they are served by file id, not session path).
- 2026-11-10: Artifacts work against the real backend instead of the planned cowork API. The listing now walks the user's recent chats (`GET /v1/agents/sessions` + per chat `GET /v1/agents/sessions/{id}/artifacts`, entries `{path, size, last_modified}`) because the backend has no global artifact index; the page's cards enrich them with the chat title and a MIME type from the file name. The bytes stream through a dedicated BFF route (`GET /api/agentry/agents/sessions/{id}/artifacts/{path}`, `?download=1` forces an attachment) that validates the segments against path escapes, answers the extension's MIME type (the upstream sends `application/octet-stream` for everything) and serves PDFs, images and text inline; docx/xlsx/pptx download directly, and `.env`-style dot files are never fetched from the browser. The old `/agents/artifacts*` allow-list rules are gone. Files an agent created also appear in the chat itself as claude.ai-style cards above the composer (re-read whenever the chat turns idle), opening the same preview dialog with Download. The listing hides the agent's tooling from the same views — dependency installs inside the session workspace (`.pylibs`, `.venv`), `__pycache__` caches, dot files — which could flood a chat with hundreds of library files after a docx built without a system-wide `python-docx` (the real fix is a backend "presented files" concept instead of enumerating the whole workspace). A DeepSeek-style "Background task updated" card is not implemented: the backend item stream has no background-job model (DeepSeek's own harness renders it), so chat cards from job notifications need a backend item type first.
- 2026-11-10: The `/` menu has three groups. Commands (backend `/compact`, `/goal`, `/feedback`, from `GET /agents/commands?session_id=`, run with `POST .../sessions/{id}/commands/{name}`; greyed out while a turn runs, 409 `session_busy` shows a notice and keeps the text), App (`/new`, `/clear`, `/model`, `/effort`, `/rename`; run in the browser, never sent) and Skills. Skills and commands load per chat and reload when the chat changes. A command's result is a `slash_command` item shown as a card in the chat (also from history and the stream). New chats also prefill from `?seed=docs|slides|data` and `?schedule=1` and then clear the query. Mock API serves the new routes.
- 2026-11-10: A cron rule the agent authored inside a task now reads like a rule the form could have made — `0 8 * * 1-5` says "Weekdays at 8:00 AM", `0 9 * * *` "Daily at 9:00 AM", `*/15 * * * *` "Every 15 minutes", `0 */2 * * *` "Every 2 hours", named weekday tokens (`MON-FRI`) included — so the detail page no longer collapses these to "Custom schedule" (day-of-month, month lists and other untranslatable expressions stay Custom). The task header also sits tighter: the actions row (active/paused switch at the left, `Run now` with its joined three-dot menu pinned to the right end of the line, above the Instructions column), and an empty history shows "No runs yet" inside a card.
- 2026-11-10: A scheduled task opens its own detail page (`/scheduled/{id}`, link from the list; `/scheduled/{id}/edit` opens it with the editor already up): claude.ai's read view — title, next run, active/paused switch, a `Run now` split button whose joined three-dot menu holds Edit and Delete; below, the delivery history (Scheduled / Delivered, Load more through `next_before`) beside the task's Instructions, Repeats and linked session. Edit opens a side drawer shaped like an automation panel: task name and instruction, Run in (current linked session), a divided Run-time card (Repeat with weekday chips for Weekly, Time with a time picker, time zone with the system zone first; `every` timings get an Interval row that translates to `every_seconds`), the linked conversation button and a Discard / Save changes footer (Save pending until something changed, posting `title, prompt, timing, revision`; a 409 `schedule_conflict` keeps the editor open). Delete confirms in place and returns to the list; 404 says the task is gone and 401 goes to sign-in.
- 2026-11-10: The Repeat menu reads like the automation panel and stays structured — "Weekly", "Monday to Friday", "Every day", "Every N hours", "Every N minutes", "Once", "Custom" — where the two "Every N …" kinds show an Interval field translated to `every_seconds` (N × 60 s / N × 3600 s); a loaded `every` timing decodes back into hourly/minutes intervals when it divides evenly and falls back to Custom cron otherwise.
- 2026-11-10: New Artifacts page (`/artifacts`, in the sidebar under Scheduled): "Make something new" tiles (Docs, Slides, Data) open a new chat with `?seed=docs|slides|data` for the composer to prefill (`/office-docx `, `/office-pptx `, `/office-xlsx `), and a grid of the files the agent created (`GET /api/agentry/agents/artifacts`, `api.listArtifacts()`, Load more) with a preview dialog (image, PDF, text; Open chat and Download). Artifact bytes stream through a dedicated BFF route that keeps `Content-Disposition` and is frameable by this origin only; `artifacts` is a reserved agent id. The mock API serves five sample artifacts.
- 2026-11-10: Scheduled-task types follow the final backend API: `after`, `every` and `rrule` timings are flat (`after_seconds`, `every_seconds`, `rrule: string`), `UpdateScheduleParams.revision` is optional (still sent for 409 handling), `CreateScheduleParams.environment` is typed, and the never-returned `source` field is gone; `at` instants render and prefill in the browser time zone.
- 2026-11-10: Typing `/` at the start of the composer lists the skills Agentry can use. The list (`GET /api/agentry/agents/skills`, now on the BFF allow-list) loads once in the background when the app shell mounts, lives in an in-memory store every composer reads, and refreshes on window focus at most once per 60 s; a failed fetch leaves the menu off without an error. The mock API serves three sample skills.
- 2026-11-10: Fonts are loaded instead of falling back to the system font (the theme named Figtree but never loaded it): Inter for text and Source Serif 4 for headings, through `next/font/google` in `app/layout.tsx` (`--font-sans`, `--font-serif`), wired into the theme's `--font-family-body` / `--font-family-heading` in `src/ui/theme/brand.ts`.
- 2026-11-10: The Scheduled page uses claude.ai's layout: a centered column (880px max, 16px side gutter) with a large "Scheduled tasks" title in the page, one row of "Yours" / "Templates" toggle chips on the left and the New task menu on the right, then the task table, or the empty state with a two-column template grid (icon, title, description, clock schedule line). The top bar and tab list are gone from this page; no behaviour changes.
- 2026-11-09: A chat shows a "thinking" row while nothing of its reply is visible yet: while the history loads ("Loading conversation…"), and from sending a message until the model's first text, thought or running tool appears ("Agentry is thinking…"), so a send no longer looks ignored. The row disappears as soon as one of those shows, and a closed stream or an unavailable server still shows its own notice instead. A chat also renders its history only once the session status is known (the first snapshot or stream frame), so it no longer flashes an empty conversation on the way in.
- 2026-11-09: A long chat has one scrollbar again. The page content slot of the trajectory layout (`src/ui/shell/SidePanel.tsx`) now bounds its children in a full-height, non-scrolling flex column: the hidden Trajectory view used to grow past its pane (it is taller than the pane whenever the ledger is long) and lengthened the shell's scroll area, giving the chat a second scrollbar and a gap under the composer.
- 2026-11-09: A failed or cancelled turn's notice stays at the end of its turn when the turn's user message reaches the chat after the notice (a message sent from another tab or client that fails at once: the stream's `turn.failed` arrives before the items refresh). It used to show above that message until a reload.
- 2026-11-09: Model and reasoning effort can change mid-chat. In an open chat the composer's model and effort menus are live and start at the session's stored values (the model menu offers the same models as a new chat, plus the session's own). The next message carries only what changed, as `model` and `reasoning.effort` on its `agent.session.input.message` event; Agentry applies them before queueing the message, and the menus then show the new stored values. Auto is offered only while the session has no stored effort, since Agentry has no value that clears it. If Agentry refuses the change (409 `session_setting_not_live`: unsupported, or the session is not live), nothing is queued: the draft stays in the composer, the backend's message shows as the composer's error, and the menus go back to the session's stored values.
- 2026-11-09: Lighter polling and review follow-ups. After the first full load, item refreshes read only the items saved after the last known one (`after=<id>`; the log is append-only), with the newest turn records (`order=desc&limit=5`) instead of every turn. The poll runs at 1.5s and backs off to 3s, then 5s, while nothing changes (any new item, turn change or subagent change resets it); it still skips hidden tabs and stops when nothing runs. Subagent reads never overlap, and opening a chat no longer refreshes again for replayed items and turn ends it already loaded. An expanded subagent card shows the items the conversation already reads instead of polling every 2s on its own (a nested card without them reads once). Cancelled turns show "Cancelled" in the trajectory (turn chip, the last step and calls without output, overview span) instead of "Completed". The reasoning repeated in front of a message is cut only on an exact leading match that ends at a boundary, so a short thought never eats the start of an answer. Renaming broadcasts the metadata map just saved, so a star made while the dialog was open is kept. While a chat's history loads, its title menu and view tabs stay (the chat is not treated as blank). "Show in chat" retries for a few frames while the row renders and shows a short notice if it never appears. The mock API honours `order=desc`. AGENTS.md describes F1.1 and lists the backend gaps it works around.
- 2026-11-09: Switching between Chat and Trajectory keeps the composer draft and the chat's scroll position: both views stay mounted and the inactive one is hidden and inert. Only the current thought streams: a Thinking block is open ("Thinking…") while it is the latest step of the running turn, and collapses to its summary as soon as the turn moves on (a tool call, the answer, or the next thought), instead of every thought of the turn staying open until it ends.
- 2026-11-09: Compact Trajectory view. Smaller text throughout; the toolbar is one slim row of icon toggles (Duration, Turns, Calls, Subcalls) with a compact Search on the right; the overview draws thin bars in labelled lanes (Turns, Subagents); ledger rows are one line with dividers, kind chips right-aligned in a fixed narrow column, previews ellipsized, and tool rows show name, arguments and "→ result" in monospace; the status chip shows only for pending or failed rows; the turn header and Event details are tighter. No behaviour changes.
- 2026-11-09: Chat title menu and starred chats. An open chat's header shows its title as a quiet button (title and a chevron, one line, ellipsized; "New chat" when untitled) above the view tabs; it opens Star / Unstar, Rename and Delete. A blank chat (the new-chat page, or a chat with nothing in it yet) shows no title. Starring saves `metadata.starred = "true"` on the session (unstarring removes the key) through `POST /agents/sessions/{id}`; Agentry replaces the whole metadata map, so the current map is read and merged first, as rename already did. The sidebar lists starred chats under a Starred section above Today / Yesterday / Earlier (not repeated below), and each row's menu gains Star / Unstar. Star changes show at once in the header and sidebar and roll back with an error toast if Agentry refuses them. Rename, delete and star now share one module (`src/ui/shell/session-actions.tsx`) used by both the sidebar and the header, and every change is broadcast on the existing `agentry:sessions-changed` window event with the new metadata, so the header and sidebar stay in step without reloading the list. Deleting the open chat from the header goes home.
- 2026-11-09: The composer's attach button moved from its own row above the input into the footer row, at the left before the model and reasoning-effort menus (as in astryx's full-featured composer). It stays disabled with its tooltip.

Buttons, cards and menus are unchanged.
- 2026-11-09: The composer's autofocus waits until its editor is enabled (a new chat's editor is disabled while the models load), so focus no longer lands on the attach button and shows its tooltip on page load.
- 2026-11-09: Full-featured composer, from astryx's `ChatComposerFullFeatured` template. The footer has a model menu (offered models) and a reasoning-effort menu (Auto, Low, Medium, High); a new chat sends the chosen effort as `agent.reasoning.effort` when the session is created (Auto sends none). In an open chat both menus show the chat's model and effort but are disabled, with the reason as a tooltip: a follow-up message cannot carry them, and Agentry's session update stores them without reaching the running agent. The model moved from the chat's top bar into the composer. An attach button is present but disabled with the tooltip "File attachments need backend support" (no upload endpoint yet); the attachments drawer appears once there are attachments. Slash commands: given a list of commands, typing `/` at the start of the message opens a menu of them (arrow keys, Enter, Escape; filtered by what follows the slash) and choosing one inserts `/name `. The app passes none until Agentry lists skills, so there is no menu and `/x` is sent as text. After a send, focus returns to the message editor (not the first button). Enter sends, Shift+Enter adds a line and Stop shows while a turn runs, as before.
- 2026-11-09: Trajectory view (replaces the per-turn trace panel). A chat's header now has two rows: the title, then view tabs (Chat, Trajectory; text tabs with the active one underlined in the accent colour), hidden on a blank chat; the chosen view is remembered per chat in this browser. Trajectory replaces the chat column (no composer) with a toolbar (Duration: actual or equal-width spans; Turns, Calls and Subcalls fold toggles; Search, which also finds folded subcalls), a timing overview (turns and subagent runs from their recorded start and end; drag to focus the ledger on an interval, wheel to zoom, right-click to clear; a 500 ms hover shows start and duration), and a ledger: a sticky "Turn N" header with Input, Output, Think and Time, then User, Assistant ("Step N", model), Tool (recorded name and argument summary) and Subtool rows (a subagent's own activity under the call that started it, folded into "N subcalls"), each with a coloured kind chip (User blue, Assistant teal, Thinking purple, Tool orange, Subtool pink) and its status. Selecting a row opens Event details in the right panel (a drawer below 768px): Token usage, Duration, Input and Output (JSON as a collapsible tree with a raw `{}` toggle and copy; other output as preserved text), Thinking, and Timing. Agentry records no per-item timestamps or per-step usage, so those show "Not recorded" or "Not available" rather than estimates. "Show in chat" switches to Chat, scrolls to that record's row and marks it briefly. The trajectory is built from the same live state as the chat, which now also keeps the turn records (stream turn frames and `GET .../turns`, read with the items), the latest item list, and each subagent's items (read with its turns; not read again once it has finished). A tool call still without output when its turn has ended no longer keeps a running spinner: it shows done with no output, or failed when the turn failed; an output that arrives later still fills it in.
- 2026-11-09: Expandable subagent activity. The proxy allows `GET` on `/agents/sessions/{id}/subagents`, `/subagents/{subagentId}`, `/subagents/{subagentId}/items` and `/subagents/{subagentId}/turns` (other methods and traversal still 404). A subagent's activity never travels on the parent stream, so the chat reads the subagents and their turns with the items (on open, after each refresh, and on the poll, which keeps running while a subagent works after its turn ended). Each subagent gets a card right after the `subagent` call that started it, named by the call's description, with live status and duration; expanding it loads the child's items and shows them with the same message, Thinking and tool views (nesting up to 3 levels). A shell command's output, which the backend saves without the command's call id, now finishes the command before it. A hidden tab no longer polls items; it refreshes when shown again. The mock's "delegate" script now behaves like the backend (a child with its own turns and items under the subagent routes).
- 2026-11-09: Reasoning and tool calls now render from what the real backend sends (fixture recorded with `scripts/record-fixture.ts` into `tests/fixtures/live/web-search.json`). The stream carries assistant messages only, so during a turn the chat refreshes the saved items shortly after each finished message or turn end and every 1.5s while the session is in progress: tool cards (`ChatToolCalls`, running until their output arrives, expandable input and output, long output capped at 20,000 characters) and Thinking blocks appear live, and the optimistic user bubble is reconciled. Items merge in log order around streamed messages. Reasoning is no longer shown as answer text: the reasoning the backend repeats in front of a saved message (and streams as the text of a reasoning-only step) is cut from it, and empty messages render nothing. Thinking is open while its turn runs and collapses afterwards to one line ("Thought" and the first line, ellipsized inside the column; the label never wraps). An answer keeps its streaming state until its turn ends. The mock now behaves like the backend (no user, reasoning or tool frames on the stream) and replays the recorded turn for messages containing "web". The e2e run builds into `.next-e2e` (`AGENTRY_WEB_DIST_DIR`) so it can run beside a dev server.
- 2026-11-09: Assistant Markdown never loads images: `![alt](url)` renders as a link labelled "Image: <alt>" (opens in a new tab, no referrer, only when clicked), so a prompt-injected image URL cannot leak conversation data on its own.
- 2026-11-09: Keycloak token refresh is single-flight: concurrent requests that find the same expiring token share one refresh call, and a just-refreshed result is reused for 30s by requests still carrying the old refresh token, so realms that revoke used refresh tokens no longer sign the user out mid-use. Only a definitive refusal from the token endpoint (400/401, e.g. `invalid_grant`) clears the session; a network error, 5xx or malformed answer keeps it and the request answers 503 `auth_unavailable`.
- 2026-11-09: Sign-out no longer sends the Keycloak ID token to the browser: the end-session URL carries `client_id` and `post_logout_redirect_uri` instead of `id_token_hint` (Keycloak asks the user to confirm). `post_logout_redirect_uri` is built from `X-Forwarded-Proto` / `X-Forwarded-Host` when present.
- 2026-11-09: Opening or reconnecting a chat waits (up to 5s) for the session snapshot before opening the stream, and a snapshot that answers after stream events have arrived is ignored, so a stale status or approval never overwrites newer ones. A stream connection that stayed open 30s resets the reconnect backoff even when it carried no events. A 403 or 404 from the stream now shows a warning banner instead of closing silently.
- 2026-11-09: Security headers on every response: a Content Security Policy (`default-src 'self'`, Google Fonts for the theme font, `img-src 'self' data:`, `frame-ancestors 'none'`, `object-src 'none'`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` and `X-Frame-Options: DENY`.
- 2026-11-09: Known gap: question cards do not support multi-select questions yet (`multiSelect` is ignored; one option or free text can be sent).
- 2026-11-08: Scaffold the Next.js app (App Router, TypeScript strict) with astryx 0.7.11 (`theme-neutral`, following the OS light/dark preference) and StyleX 0.19.1. Server configuration is validated at startup: a missing or invalid `AGENTRY_WEB_AUTH`, `AGENTRY_API_URL`, `AGENTRY_WEB_SESSION_SECRET` (≥ 32 bytes) or Keycloak variable stops the server with a named `ConfigError`; optional `AGENTRY_WEB_MODELS` lists the offered models. Adds Vitest and Playwright setup.
- 2026-11-08: Add the encrypted `agentry_session` cookie (iron-session; `HttpOnly`, `SameSite=Lax`, `Secure` in production, chunked when large). A tampered cookie or rotated secret reads as signed out. Each session carries a CSRF token; state-changing requests must be same-origin and send it in `x-agentry-csrf`. Only the identity (owner, roles, display name) is ever exposed to the browser.
- 2026-11-08: Add sign-in at `/login`. In apikey mode the key is checked with one Agentry call (`GET /v1/agents?limit=1`), kept only in the encrypted session, and never echoed; a rejected key answers 401 `invalid_key`, and the identity shows as "API key user". In keycloak mode Auth.js runs the authorization-code flow with PKCE and state; tokens go only into the encrypted session, and access tokens are refreshed 60s before expiry (a failed refresh signs out). `POST /api/auth/logout` (same-origin + CSRF header) clears the session and returns the Keycloak end-session URL with `id_token_hint` (or `/login` in apikey mode).
- 2026-11-08: Add the Agentry proxy at `/api/agentry/*`: only F1's allow-listed `/v1` routes pass (agents read and tools list; sessions create/list/get/update/delete; events post; items; turns), everything else answers 404, and id segments must match `[A-Za-z0-9_-]+`. The proxy adds the server-side credential and `OpenAI-Beta: agents=v1`, never forwards browser cookies or authorization, and requires same-origin plus the CSRF header for `POST`/`DELETE`. `GET /api/agentry/sessions/{id}/stream` passes Agentry's SSE through unbuffered and forwards `Last-Event-ID`. An Agentry 401 clears the session and answers 401 `signed_out`.
- 2026-11-08: Add the Agentry wire types used by F1 (copied from the backend's `src/types.ts`, with the provisional approval/question action and `approval_response` input from backend Task 6) and the conversation reducer. The reducer folds stream events and saved items into user, assistant (streamed), reasoning, tool, delegation, action and notice views; durable events are applied once by SSE id (duplicates and replays up to the last id are ignored), id-less events update status and approvals without moving the last id, and failed, interrupted or stopped turns add an inline notice.
- 2026-11-08: Add the conversation stream hook, the browser API client and the mock Agentry server. `useConversation` opens `/api/agentry/sessions/{id}/stream` with `Last-Event-ID: 0` (Agentry replays the history, then continues live) and applies the session resource as a status snapshot so pending approvals show; a lost stream retries after 1s, doubling to a 30s cap, with the last seen id, and retries at once when the tab becomes visible; a 401 goes to `/login`. Pending approvals and questions always render after the conversation. The API client calls only the web app's own routes, sends the CSRF token from `<meta name="agentry-csrf">`, and throws `ApiError` (status, code, message); sign-out falls back to `/login` when the session is already gone. New `GET /api/models` lists `AGENTRY_WEB_MODELS` first, then the models of the user's saved agents. `pnpm mock:api` runs an in-memory Agentry on port 4010 with scripted replies (approval, question, slow, tool, delegate, failure), `Last-Event-ID` replay, and `POST /__mock/drop` to drop open streams.
- 2026-11-08: Opening a chat now loads its saved items first and then replays the stream from `Last-Event-ID: 0`, so reopened chats show user messages, tool calls and reasoning, which the stream does not carry. Replayed events update the views the items created by id, so the same message never shows twice and finished text is never doubled. Notices and delegation cards from replayed turns stay inside their turn, and a reply after a steering message follows it. Reconnects still resume from the last seen id without reloading items.
- 2026-11-08: Add the signed-in app shell. Every page outside `/login` now requires a session (signed-out visits go to `/login`) and carries the CSRF token in `<meta name="agentry-csrf">`. The sidebar lists the user's chats newest first, grouped Today / Yesterday / Earlier by local date, loads more as it scrolls, filters by title, and renames (session metadata title) or deletes a chat after confirmation; its collapsed state is remembered in `localStorage`, and below 768px it becomes a drawer. The user menu shows the owner and roles and signs out. The UI uses the Agentry theme (theme-neutral plus a teal accent and the Agentry wordmark); the light / dark / system choice is read from the `agentry_theme` cookie so the server renders it on first paint.
- 2026-11-08: Add the chat. `/` shows a large composer with the model picker (models from `GET /api/models`; the default comes from the `agentry_model` cookie); the first message creates the session and opens `/c/{id}`. A conversation shows user bubbles, streamed assistant Markdown (astryx Markdown: GFM tables, code blocks with copy, KaTeX math, raw HTML never parsed), collapsed "Thinking" blocks, tool cards that expand to the full input and output, "Delegated to …" cards, approval cards (Allow / Deny) and question cards (options or free text), and inline notices with Retry for failed, interrupted or stopped turns. The streaming reply is a polite live region, and reduced motion turns off the streaming fade. A "Reconnecting…" pill shows while the stream is down. Adds the Playwright end-to-end suite against the mock API and `docs/live-check.md`.
